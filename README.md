# Students & Rooms

Загрузка данных о студентах и комнатах из JSON-файлов в PostgreSQL, выполнение четырёх
SQL-запросов и выгрузка результата в JSON или XML. Без ORM: только SQL (psycopg2),
все вычисления выполняются на стороне БД.

## Быстрый старт (Docker)

Нужен только запущенный Docker Desktop (или Docker Engine с плагином Compose).

```bash
cp .env.example .env.local
# откройте .env.local и заполните DB_NAME, DB_USER, DB_PASSWORD

make up                 # результат в формате JSON
make up FORMAT=xml      # результат в формате XML
```

Что происходит:

1. Поднимается PostgreSQL и ждёт, пока сервер начнёт принимать подключения (healthcheck).
2. Запускается приложение: создаёт таблицы, загружает `data/rooms.json` и `data/students.json`,
   создаёт индексы, выполняет запросы.
3. Результат записывается в `output/result.json` или `output/result.xml`, контейнеры останавливаются.

Данные БД сохраняются между запусками (том `pgdata`), повторный запуск безопасен.
База доступна снаружи на порту `5433` (для DBeaver и подобных программ).

Без Makefile то же самое делает команда:

```bash
FORMAT=json docker compose -f docker/docker-compose.yml --env-file .env.local up --build --abort-on-container-exit --exit-code-from app
```

Остановка и полная очистка данных БД:

```bash
make down      # остановить контейнеры
make reset     # остановить и удалить данные БД
```

## Запуск без Docker

Требуется Python 3.10+ и доступный сервер PostgreSQL.

```bash
make install            # создаёт .venv и ставит зависимости
cp .env.example .env.local
# заполните все пять переменных (DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD)

make run                # формат JSON
make run FORMAT=xml LOG_LEVEL=DEBUG
```

Если сервера PostgreSQL нет, можно поднять только базу из compose-файла:

```bash
docker compose --env-file .env.local up -d db
```

Тогда в `.env.local` укажите `DB_HOST=localhost` и `DB_PORT=5433`.

Вручную, без Makefile:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
set -a; source .env.local; set +a
python3 -m src.cli --format json
```

Запускать нужно из корня проекта.

### Переменные окружения

Значений по умолчанию нет. Если переменная не задана или пуста, программа останавливается
с сообщением, какой переменной не хватает.

| Переменная    | Описание                                                       |
|---------------|----------------------------------------------------------------|
| `DB_HOST`     | адрес сервера БД (в Docker подставляется автоматически)         |
| `DB_PORT`     | порт БД, целое число (в Docker подставляется автоматически)     |
| `DB_NAME`     | имя базы данных                                                |
| `DB_USER`     | пользователь                                                   |
| `DB_PASSWORD` | пароль                                                         |

Файл `.env.local` не попадает в репозиторий. Шаблон лежит в `.env.example`.

## Параметры командной строки

```bash
python3 -m src.cli --format {json,xml} [--rooms ПУТЬ] [--students ПУТЬ] [--output ПУТЬ] [--log-level УРОВЕНЬ]
```

| Параметр      | Обязательный | По умолчанию                | Описание                                   |
|---------------|--------------|-----------------------------|--------------------------------------------|
| `--format`    | да           | —                           | формат результата: `json` или `xml`        |
| `--rooms`     | нет          | `data/rooms.json`           | путь к файлу с комнатами                   |
| `--students`  | нет          | `data/students.json`        | путь к файлу со студентами                 |
| `--output`    | нет          | `output/result.<формат>`    | куда записать результат (папка создаётся)  |
| `--log-level` | нет          | `INFO`                      | `DEBUG`, `INFO`, `WARNING`, `ERROR`        |

Код возврата: `0` при успехе, `1` при ошибке (сообщение выводится одной строкой),
`2` при неверных параметрах.

## Входные и выходные данные

### Входные файлы (`data/`)

`rooms.json`:

```json
[{"id": 0, "name": "Room #0"}]
```

`students.json`:

```json
[{"id": 0, "name": "Peggy Ryan", "birthday": "2011-08-22T00:00:00.000000", "sex": "M", "room": 473}]
```

Поле `room` в студенте это `id` комнаты.

### Результат (`output/`)

Один файл со всеми четырьмя запросами. В JSON это объект с четырьмя ключами, в XML корневой
элемент `<result>` с четырьмя вложенными элементами, внутри каждого `<row>` с полями.

```json
{
  "rooms_students_count": [{"id": 0, "name": "Room #0", "count_students": 9}],
  "lowest_avg_age_rooms": [],
  "largest_age_diff_rooms": [],
  "mixed_sex_rooms": []
}
```

## База данных

Таблицы (`sql/schema.sql`):

- `rooms (id, name)`;
- `students (id, name, birthday, sex, room_id)`, где `room_id` ссылается на `rooms.id`
  (связь many-to-one: много студентов в одной комнате).

Особенности загрузки:

- Загрузка идёт пачками (`execute_values`), а не по одной строке.
- Вставка выполняется через `INSERT ... ON CONFLICT (id) DO UPDATE`, поэтому программу
  можно запускать повторно без ошибок и дублей.
- Всё выполняется **в одной транзакции**: если любой шаг завершится ошибкой, изменения
  откатываются целиком.
- Порядок: схема, комнаты, студенты (из-за внешнего ключа), индексы, запросы.
- SQL-скрипты идемпотентны (`IF NOT EXISTS`).

## Запросы

Тексты лежат в `sql/queries/`. Возраст считается в **целых годах** функцией
`EXTRACT(YEAR FROM AGE(CURRENT_DATE, birthday))`, поэтому результат зависит от даты запуска.

| № | Файл | Что возвращает |
|---|------|----------------|
| 1 | `01_rooms_students_count.sql` | все комнаты и число студентов в каждой (пустые комнаты тоже, `LEFT JOIN`) |
| 2 | `02_lowest_avg_age.sql` | 5 комнат с наименьшим средним возрастом |
| 3 | `03_largest_age_diff.sql` | 5 комнат с наибольшей разницей в возрасте (максимальный возраст минус минимальный) |
| 4 | `04_mixed_sex_rooms.sql` | комнаты, в которых живут студенты разного пола (`HAVING COUNT(DISTINCT sex) > 1`) |

Правила выбора при равных значениях:

- запрос 2: сортировка по точному среднему, при равенстве по `id` комнаты;
- запрос 3: сортировка по разнице в целых годах, при равенстве по разнице между датами
  рождения в днях (больше значит выше), затем по `id` комнаты. Разница в годах целая,
  поэтому одинаковых значений много, и без второго критерия топ-5 определялся бы только номером комнаты.

Среднее возраста в запросе 2 это среднее целых возрастов, поэтому оно дробное
(округляется до двух знаков только в выводе).

Проверочные запросы на небольшом наборе данных: `sql/test_queries.sql`.

## Индексы

Скрипт `sql/indexes.sql` создаёт три отдельных индекса по таблице `students`:
`idx_students_room_id (room_id)`, `idx_students_birthday (birthday)`,
`idx_students_sex (sex)`.

В PostgreSQL внешний ключ автоматически индекс не получает, поэтому индекс по `room_id`
нужен для соединения с `rooms` и группировки по комнатам.

| 2      | <...>            | <...>           | <...>                      |
| 3      | <...>            | <...>           | <...>                      |

Индексы не бесплатны: они занимают место и замедляют вставку, поэтому создаются
после массовой загрузки. На малых объёмах выигрыш невелик и растёт вместе с таблицей.
Возраст вычисляется функцией над датой рождения, поэтому индекс по `birthday` в наших
запросах не может заменить вычисление, а индекс по `sex` малоселективен (два значения).

## Архитектура

Каждый класс отвечает за одну задачу, зависимости передаются через конструктор.

```
cli.py → Application ─┬─ DataLoader (JsonLoader)      чтение файлов → Room, Student
                      ├─ DataBaseConnection           соединение и транзакция
                      ├─ RoomRepository, StudentRepository   пакетная вставка
                      ├─ QueryService                 4 запроса из sql/queries/
                      └─ Exporter (JsonExporter, XmlExporter)  результат → строка
```

- `Application` зависит от абстракций `DataLoader` и `Exporter`, конкретные классы
  подставляются в `cli.py`.
- `ExporterFactory` выбирает экспортёр по названию формата.
- Новый формат вывода: написать подкласс `Exporter`, добавить его в словарь
  `ExporterFactory` и в `choices` параметра `--format` в `cli.py`.
- Новый формат входных данных: подкласс `DataLoader`.

## Логирование

Модуль `logging`, настройка в одном месте (`src/logging_config.py`). Логи пишутся в `stderr`,
чтобы не смешиваться с результатом. Уровень задаётся параметром `--log-level`.
Пароли в логи не попадают.

## Тесты

Юнит-тесты не требуют базы данных и переменных окружения (соединение и репозитории подменяются
mock-объектами):

```bash
make test
# или: pip install -r requirements-dev.txt && pytest -v
```

Покрыто: конфигурация, загрузчик, экспортёры и фабрика, поведение соединения (commit/rollback,
использование вне `with`), репозитории, порядок шагов `Application`, параметры CLI.

## Ограничения

- Входной JSON читается в память целиком. Для файлов в гигабайты нужен потоковый разбор.
- Загрузка добавляет и обновляет строки, но не удаляет: если запись пропала из файла,
  в БД она останется. Для полной синхронизации таблицы нужно очищать.
- Возраст считается относительно даты запуска, поэтому результаты запросов 2 и 3 со временем меняются.
